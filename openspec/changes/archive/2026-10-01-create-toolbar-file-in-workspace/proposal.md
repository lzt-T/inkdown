## Why

用户希望新文件归属当前文件夹，并沿用文件树右键新建 Markdown 的命名体验。顶部“新建文件”已接入工作区根目录命名流程，但欢迎页同名按钮仍直接创建无磁盘路径的文档，需要统一这两个界面入口的行为。

## What Changes

- 已有工作区时，顶部和欢迎页的新建入口在工作区根目录显示新建 Markdown 的树内命名行，默认 `未命名.md`，重名时自动编号。
- 确认名称后在根目录创建文件，刷新文件树，并打开为活动文档；取消命名不创建文件。
- 为完成树内命名，主动显示侧栏并切换至“文件”页签。
- 没有工作区时，两个入口均保留新建未保存文档、首次保存选择路径的行为。
- 欢迎页命名阶段保持欢迎页可用，确认创建成功后才打开新文档；取消命名不产生空白标签。
- 本次调整顶部和欢迎页入口；文件树右键入口保持其原有目标目录及提交行为，快捷键保持现状。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `file-open-workspace`: 更新“保持无目录文档和侧栏偏好”，统一顶部与欢迎页在有工作区和无工作区时的创建行为，并明确树内命名、创建后打开及侧栏显示规则。

## Impact

- 涉及 `Titlebar.tsx` 的新建入口、`App.tsx` 的组件通信与侧栏切换、`FileTree.tsx` 的根层命名行和提交逻辑；欢迎页补充通过 `EditorPane.tsx` 向 `Welcome.tsx` 传递同一新建回调。
- 复用现有默认名称计算、`window.api.file.create`、目录刷新和文件打开能力，不新增依赖或 IPC。
- 更新现有规格的一项要求，不改变其他打开文件入口的目录规则。
