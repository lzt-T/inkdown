## Context

动机见 `proposal.md`。顶部入口已通过 `App` 的 `handleNewFile` 接入根目录命名流程；树内编辑状态已提升到 `App`，`FileTree` 复用 `EditingRow`、默认名称映射和 `getAvailableName`，提交调用 `window.api.file.create` 后刷新父目录并按来源决定是否打开。

根层命名行已实现。欢迎页由 `App → EditorPane → Welcome` 渲染，其“新建文件”仍直接调用 `newUntitled`；本次增量只需将同一新建回调传到欢迎页。原生菜单的新建命令独立调用 `newUntitled`，保持该入口现状。

## Goals / Non-Goals

**Goals:**
- 以同一份树内编辑状态衔接顶部、欢迎页入口与文件树，复用现有命名组件、名称规则、创建 IPC 和文档打开流程。
- 欢迎页增量只增加必要的回调传递，不复制工作区判断或创建流程，不引入事件中心、命令框架或新的依赖。

**Non-Goals:**
- 不调整菜单、快捷键或子目录右键入口的产品行为。
- 不重构工作区生命周期、保存机制及其他文件操作。

## Decisions

### 1. 顶部与欢迎页入口以工作区根为唯一目标

两个入口共用 `App` 中已有的 `handleNewFile`，在点击时读取当前根目录。没有根目录时继续调用 `newUntitled`；有根目录时返回编辑界面、通过现有侧栏操作显示文件页签，并启动根层命名流程。目标不随活动文档所在目录变化。欢迎页不在命名开始时创建标签，确认创建成功后由既有打开流程自然切换到编辑文档。

不采用直接创建默认文件的方案，因为需要保留用户确认名称的树内交互；不使用保存对话框，因为目录已经确定。

### 2. 共享 UI 状态放在最近公共父组件

树内编辑状态保持在 `App`，通过 props 和回调连接 `Titlebar`、`FileTree`；为 `EditorPane` 增加 `onNewFile` 回调并传递给 `Welcome`，欢迎页按钮调用该回调并移除本次造成未使用的 `newUntitled` 订阅。名称输入仍在 `FileTree` 内渲染，磁盘操作仍沿用其提交入口；`App` 只负责 UI 状态与入口协调。

将必要的编辑类型和默认名称计算放在文件树所属的小型模块，供两处复用；避免让业务 store 持有输入框编辑值，也避免同时保存新建请求和编辑状态两份来源。替代方案是发布事件或使用组件命令 ref，但兄弟组件已有明确公共父节点，直接通信更简单。

### 3. 根层复用现有编辑行

根层创建使用工作区根作为 `parent`、深度 0，并沿用默认名称、编号、回车/失焦提交和 Escape 取消规则。只有一个编辑状态，重复点击不会出现多个命名行。空目录时隐藏干扰命名的空态提示。

工作区切换或关闭时清除不再属于当前根的编辑状态，避免旧命名行提交到先前目录。顶部按钮可直接请求焦点；子目录右键继续保留菜单关闭后聚焦的处理。

### 4. 使用实际创建结果打开文档

顶部和欢迎页共用已有的创建后打开标记；无需为欢迎页增加独立来源分支。子目录右键创建保持既有提交行为。提交先关闭命名行以避免重复提交，使用创建 IPC 返回的实际路径刷新并打开，避免自己拼接名称后忽略后台重名处理。

创建失败沿用操作失败提示，不新建内存标签。刷新失败与创建失败区分：已创建的文件仍应尝试打开，目录失败使用现有提示，不将它描述为磁盘创建失败。

## Risks / Trade-offs

- [侧栏偏好发生变化] → 仅为顶部和欢迎页命名入口主动显示文件页签；普通打开文件保持既有侧栏偏好。
- [命名期间目录变化或名称冲突] → 根切换时清理编辑状态；默认编号复用现有计算，最终路径以创建 IPC 的返回值为准。
- [文件行数接近限制] → `FileTree.tsx` 已接近 500 行，优先将本次需要共享的类型和名称计算放入职责明确的小模块；不拆分无关 UI。已有大型 store 无需为本次 UI 通信扩大重构。
- [自动化验证受限] → 不执行未经授权的 package.json 脚本，不控制浏览器；实施时完成源码检查并明确列出未执行的动态验证。

## Migration Plan

不涉及持久化格式或依赖迁移。顶部与根层命名已完成，本轮按新增任务接入欢迎页并检查有/无工作区分支；本轮回滚只撤销欢迎页回调传递，保留已完成的顶部行为。
