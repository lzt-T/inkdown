## Context

动机与范围见 proposal.md。项目采用 Electron、React、Zustand、Milkdown 与 CodeMirror，包管理器为 pnpm。现有 `src/main/state.ts` 将设置写入 `state.json`，共享契约中的 `PersistedState` 经 preload 设置接口传给渲染端。

应用文案分散在组件、静态配置、Store、Hook 与主进程。`MilkdownSurface` 固定传入 `locale="zh-CN"`，已安装的 `zt-react-milkdown` 文档声明支持 `zh-CN`、`en-US` 和自定义 messages，但不能仅凭 Props 声明确认热切换保留编辑历史。CodeMirror 当前没有配置语言短语。现有 file-open-workspace 规格固定中文默认文件名，需同步增量规格；拼写检查和最近记录的行为不变。

## Goals / Non-Goals

**Goals:**
- 用共享资源与唯一持久化偏好协调主进程和渲染端，避免各自判断系统语言。
- 优先复用现有设置页、IPC 与编辑器的语言接口，离线加载，不扩大无关组件的重构范围。
- 在翻译切换时保留编辑实例状态，文案更新不触发文件操作或内容修改。

**Non-Goals:**
- 不搭建翻译服务，不引入浏览器语言探测插件，不新增全局事件总线。
- 不改变文档格式、工作区生命周期、排序与拼写检查规则。
- 不监听运行期间的系统语言变化；“跟随系统”在启动及重新选择时解析。

## Decisions

### 1. 分离持久化偏好与实际语言

共享契约新增 `LanguagePreference = 'system' | 'zh-CN' | 'en-US'` 与实际语言类型，`PersistedState` 保存 `language: 'system'` 默认值。主进程在 Electron ready 后用 `app.getLocale()` 解析系统语言；主语言为 zh 则 zh-CN，其余为 en-US。手动偏好直接映射为实际语言。

现有 settings get/set 返回契约扩展为包含持久化状态和只读 `resolvedLocale` 的设置快照；只读解析结果不写入 state.json，也不允许作为更新字段。主进程先保存偏好并更新自身语言与菜单，再返回快照，渲染端据此调用语言切换。只有写入成功才提交渲染端偏好，失败沿用当前语言并显示当前语言的失败提示。

替代方案：只存实际语言会丢失跟随系统的意图；renderer 使用 navigator.language 会形成两个语言来源。复用现有设置调用返回结果即可协调目前单窗口架构，无需增加广播链路。

### 2. 使用 i18next 和 react-i18next，共享离线资源

引入成熟的 i18next 与 react-i18next。共享目录保存按语言、业务域组织的翻译资源、语言类型及解析纯函数；资源随构建打包。主进程和渲染端各持有 i18next 实例，不能假设跨进程共享实例。React 使用 useTranslation，Store/Hook 外工具和主进程使用各自实例的 t。翻译资源按业务域拆分，避免单文件膨胀。

使用语义 key 和插值/复数能力，缺失条目回退英文；开发验证必须检查两种语言 key 及插值一致性，不能用回退掩盖缺失翻译。固定配置数组保存 key，在渲染或操作发生时翻译，禁止模块加载时固定翻译结果。

替代方案：自写字典会重复实现 React 更新、插值与复数逻辑；远程加载资源增加离线依赖。无需语言探测和 HTTP backend 插件。

### 3. 启动先确定语言，切换复用现有设置入口

主进程加载偏好并初始化翻译后构建菜单与窗口。renderer 首次挂载 App 之前读取设置快照并初始化 i18next，避免先显示默认中文再跳变；已有启动工作区恢复逻辑复用该快照，避免增加相互竞争的初始化流程。设置页在现有外观分类添加语言选择控件，语言自称保持“简体中文”“English”，“跟随系统”随界面翻译。

偏好只保存在 state.json，不在 localStorage 或多个 Store 中重复保存；React 文案订阅 i18next 的语言更新。切换同步更新 document.documentElement.lang、原生菜单及后续弹窗，已打开的 OS 弹窗不强制重建。Electron role 菜单项保留 role 行为并给应用可控项提供翻译 label；OS 控制的服务菜单等遵循平台能力。

### 4. 源码编辑器通过原生配置更新语言，Milkdown 延期

用户明确要求先不处理 Milkdown。保留现有 zt-react-milkdown 版本及固定 zh-CN locale，不提交任何依赖补丁，不改变 Milkdown 的占位文案与编辑器生命周期；其图片导入通知属于应用反馈，随应用语言翻译。编辑器能力核查记录保留为后续参考。

CodeMirror 使用 EditorState.phrases 覆盖交互短语，通过现有封装的 StateEffect.reconfigure 更新扩展，不重新创建编辑器。已经打开的搜索面板通过现有 closeSearchPanel/openSearchPanel 重新读取短语，并保留搜索查询、编辑器状态、滚动和原控件焦点。动态表现仍需人工验收。

### 5. 只在创建时生成名称，错误提示按边界处理

文件树、顶部、欢迎页与未保存文档入口在操作发生时获取本地化默认名，继续复用 getAvailableName 的避重编号。切换不改写已有对象名称和命名输入；首次保存沿用该文档创建时的名称。增量规格保留原有工作区场景，仅调整默认名称及对应示例。

主进程提供的应用级校验/错误说明使用当前实例翻译，renderer 显示的操作失败标题使用 renderer 翻译；第三方或 OS 原始错误详情保留原值。最近路径不存在的友好提示继续遵守既有“不暴露底层 IPC 或文件系统错误”的要求。无需为国际化改造整个 IPC 错误协议。

## Risks / Trade-offs

- [Milkdown 尚不支持安全的语言热切换] → 本次保留其原有语言参数，不提交封装修复，英文界面的 Milkdown 内部文案仍显示中文。
- [英文文案更长] → 检查设置导航、按钮、状态栏、通知和弹窗的截断/换行，只调整本次文案影响的布局。
- [模块常量或已存状态保留旧文案] → 常量保存 key，运行时翻译；已有文档名称按数据处理，避免语言切换批量改写。
- [OS 控制的原生文案无法随应用语言切换] → 验收应用提供的标题、详情、自定义按钮与可控菜单项；平台自身文案遵循系统。
- [缺少动态检查权限] → 保持浏览器控制禁令，提供人工验收步骤，未执行的状态保留明确标记。

## Migration Plan

1. 保留编辑器能力核查记录并明确 Milkdown 延期，新增共享资源和设置偏好，旧配置通过现有默认合并兼容。
2. 接通主进程解析、设置快照、启动初始化和语言选择，再按业务域迁移界面及原生文案。
3. 接入编辑器语言与默认名称，检查两种资源一致性和原有工作区行为。
4. 在明确授权后使用 pnpm 添加依赖；package.json 脚本只有用户明确命令执行时运行，不以调用脚本内容绕过。动态界面与编辑状态留给人工验收。
5. 回滚代码与新增依赖即可撤回界面行为；新增偏好字段不会改写用户文档，旧版本可忽略该字段。提案阶段不安装依赖、不执行项目脚本。
