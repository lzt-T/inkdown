## Context

动机见 `proposal.md`。当前文件对话框与按路径打开入口均读取数据后调用 Store 的 `openData`，只更新文档。`FileTree` 依赖 `workspaceRoot`、`treeNodes` 和 `expandedDirs`，没有根目录时显示“未打开文件夹”。

现有 `workspace.openPath` 已完成扫描、最近工作区持久化和监听启动，可直接复用。`App.tsx` 目前通过独立 Effect 执行历史工作区恢复和系统文件队列消费，存在启动时交错完成的可能。渲染层 `dirname` 将盘符根下文件的父目录返回为 `D:`，该值在主进程解析时不等价于 `D:\`，实现时需作任务范围内修正。

## Goals / Non-Goals

**Goals:** 在 Store 层统一文档打开后的目录协调，复用工作区能力，明确启动顺序与错误边界。

**Non-Goals:** 不为目录来源增加显式/隐式模式状态，不重做文件树 UI，不引入多根工作区，不扩大到保存、另存为或普通标签切换。

## Decisions

### 1. 在共同的文件打开流程中协调目录

保留 `openData` 的文档写入职责，在对话框与 `openPath` 共用的打开后流程中执行目录协调，两个入口均等待协调结束。目录根按“无根或根外 → 文件父目录；根内 → 当前根”确定，再复用现有工作区加载与目录展开能力。只增加一个小型协调入口，避免组件 Effect 与文件树组件重复发起扫描。

备选是在 `FileTree` 中监听活动文档；这会让目录加载依赖侧栏挂载状态，并连带改变标签切换行为，不采用。

### 2. 根内展开祖先，根外切换父目录

根内文件复用路径归属工具，按从根到父目录的顺序加载尚未缓存的目录并展开，合并已有展开列表。路径比较与缓存键须兼容 Windows 分隔符；盘符根保持绝对路径形式，避免重复目录键。当前高亮复用既有活动文件状态。

根外文件切换至自身父目录，保留所有已打开文档。备选是保留旧根或计算共同祖先；前者无法展示新文件，后者可能扩大至整块磁盘，不采用。该根外规则是本提案对跨目录打开行为的明确选择。

### 3. 直接复用工作区持久化与监听

自动父目录使用 `workspace.openPath`，与显式打开文件夹一样更新最近工作区和 `lastWorkspace`，切换现有单工作区监听。无需新增 IPC、依赖或持久化字段。

备选是建立临时只读目录上下文；需要另行区分恢复、监听与文件操作语义，超出本需求，不采用。

### 4. 文件读取和目录加载使用独立错误边界

文件读取成功即保留文档；目录协调单独捕获错误，显示简洁目录失败提示。不要将目录错误抛到 `openPath` 的文件缺失处理分支，也不要在自动协调中调用会清理最近工作区记录的恢复错误流程。仅在工作区快照成功返回后提交新树状态。

评估并以最小修改确保主进程工作区扫描失败时保留原授权与监听；当前授权在扫描前切换，若失败会与渲染层旧根不一致。复用现有 IPC 时应在成功扫描后切换授权，不扩展成通用事务框架。

### 5. 明确启动顺序

设置初始化与历史根恢复完成后，再顺序消费系统文件请求；期间到达的请求仍保留在现有队列中。复用现有请求队列，避免不同消费批次同时执行，也避免历史恢复的晚到结果覆盖文件父目录。不以额外定时器解决时序问题。

备选是只在渲染层忽略过期结果；主进程已经切换监听和持久化，因此单纯忽略结果不足以保证一致性。

## Risks / Trade-offs

- [父目录自动进入最近工作区] → 明确采用现有语义，无数据迁移；用户显式打开文件夹仍可覆盖当前根。
- [盘符根目录或 Windows 路径格式导致扫描错误] → 验收 `D:\docker.md` 和混合分隔符，针对本次使用的路径工具修正，不迁移无关代码。
- [目录扫描失败被当成文件失效] → 分开两个错误边界，保留文档和最近文件。
- [启动恢复与系统请求交错导致根、监听、最近记录不一致] → 顺序执行初始化和文件队列消费。
- [Store 已有 588 行] → 本次仅增加目录协调所需的最小逻辑；不因行数顺带拆分保存、最近记录等无关职责。若协调逻辑明显膨胀，仅提取其纯路径计算。

## Migration Plan

无需持久化格式迁移。发布后按现有工作区加载逻辑写入父目录记录；回滚实现即可恢复旧打开行为，已写入的最近工作区仍是合法目录记录。

实施验收以规格场景为依据。遵守浏览器控制禁令，不执行未获用户授权的 `package.json` 脚本，也不通过直接调用脚本内容绕过限制；受限动态检查须明确记录为未验证。
